# Постпроцессор TEI XML от GROBID: класс `Preprocess_using_grobid`

Этот класс — **постпроцессор TEI XML от GROBID**. Он берёт XML, который вернул GROBID,
и превращает его в структурированное представление документа: **словарь, где для
каждой страницы PDF собран упорядоченный список блоков (заголовки, параграфы,
формулы) с координатами и текстом**. По сути, это «мост» между семантической
разметкой GROBID и визуальным/пространственным представлением PDF.

## Что делает `.fit(grobid_xml)`

### Шаг 1. Чтение XML
`read_file_xml_to_bs4` читает TEI XML и оборачивает его в `BeautifulSoup` с парсером
`"xml"`. Дальше весь код работает через суп.

### Шаг 2. Извлечение заголовочной информации
`extract_header_info` вытаскивает из `<teiHeader>`:
- `title`, `publisher`, `date_published`;
- список авторов (сопоставляет `forename` + `surname` + `email` + `orgName` через
  `zip` — правда, это хрупко, если у автора нет email или организации);
- `keywords` из `<keywords><term>`;
- `abstract` из `<abstract>`, склеивая все `<s>`;
- `resolution` — список `[lrx, lry]` из `<facsimile><surface>`, то есть размеры
  каждой страницы в точках PDF;
- `page_count` — количество страниц.

### Шаг 3. Рендер страниц PDF в PNG
`write_images` через `pdf2image.convert_from_path` рендерит все страницы PDF
(имя PDF получается заменой `.tei.xml` → `.pdf`) в PNG с помощью `pdftocairo`.
Изображения складываются в подпапку `images/` рядом с PDF. Если папка уже есть —
она удаляется и создаётся заново.

### Шаг 4. Сбор «больших блоков» из TEI
`get_paragraph_information` берёт из `<body>` и `<back>` все теги `head`, `p`,
`formula`. Это и есть «большие блоки» — заголовки, параграфы и формулы. Порядок
сохраняется таким, как он идёт в XML.

### Шаг 5. Извлечение координат из тегов
`big_blocks_tags_to_coords` обрабатывает каждый тег по-разному:

- **`<head>`** — берёт `coords`, парсит, превращает в `[page, (x1,y1), (x2,y2)]`.
- **`<formula>`** — то же самое.
- **`<p>`** — сложнее. Сначала пытается взять `coords` у самого `<p>`. Если их
  нет — идёт в `extract_coords_for_para`, которая работает с `<s>` (предложениями)
  внутри параграфа.

### Шаг 6. Логика работы с параграфами (`extract_coords_for_para`)
GROBID с `teiCoordinates` часто даёт координаты не у всего `<p>`, а у каждого
`<s>` внутри. Каждое `<s>` может:
- лежать на одной странице (несколько строк, склеенных в один `coords` через `;`);
- занимать несколько страниц (тогда строка `coords` содержит точки с разными
  номерами страниц).

Класс разбирает это так:
- `extract_coords` / `convert_coords` — парсят строку
  `page,x,y,w,h;page,x,y,w,h;...` в список кортежей.
- `merge_dumb` — если все координаты на одной странице, берёт min/max по x и y и
  получает общий bounding box.
- `smart_merge` — восстанавливает bounding box не как прямоугольник min/max, а
  как **многоугольник из 5–6 точек**, повторяющий «змейку» текста (строка
  слева-направо, потом возврат влево на следующей строке). Это нужно, чтобы
  рамка не захватывала пустое пространство справа от коротких строк.
- Если параграф разорван между страницами, `extract_coords_for_para` делит его
  по страницам, для каждой страницы делает свой бокс и сохраняет текст
  (на первой странице — весь текст, на последующих — пустой, чтобы не
  дублировать).

### Шаг 7. Рескейл координат (`rescale`)
Координаты GROBID — в **точках PDF** (единицы 1/72 дюйма). А картинки PNG
отрендерены с другим DPI. Поэтому `rescale` для каждой страницы читает PNG через
OpenCV, сравнивает его размеры с `resolution` из TEI и вычисляет масштабные
коэффициенты `scale_x`, `scale_y`. Все боксы умножаются на них — теперь координаты
соответствуют пикселям PNG.

### Шаг 8. Группировка по страницам
`coords_to_dict` делает из плоского списка блоков словарь `{page_no: [блоки]}`.

### Шаг 9. Устранение вложенных и пересекающихся боксов
- `filter_self_containing_boxes` → `sub_boxes_single_update` → `compare_blocks`:
  если один бокс **полностью вложен** в другой, они объединяются, а тексты
  склеиваются через `return_text` (порядок определяется по индексам в исходном
  XML). Это нужно, потому что GROBID иногда даёт координаты и для `<p>`, и для
  `<s>` внутри него.
- `merge_overlaps` → `merge_overlaps_single_update` → `get_iou`: если IoU двух
  боксов **> 0** (то есть они пересекаются), они тоже сливаются, а текст
  склеивается по порядку (левый сначала).

Оба процесса запускаются в цикле, пока есть что объединять.

### Шаг 10. Пространственная сортировка
`sort_coordinates_in_dict` для каждой страницы превращает список в `DataFrame` и
сортирует по `top_left_y, top_left_x, bot_right_y, bot_right_x`. Это
восстанавливает **естественный порядок чтения**: сверху вниз, слева направо.
На выходе — список вида:

```python
[page_no, (top_left_x, top_left_y), (bot_right_x, bot_right_y), text]
```

### Шаг 11. (Опционально) Визуализация
Если `show_results=True`, `visualize_boxes` рисует каждый бокс на соответствующей
PNG через OpenCV и показывает окно, где:
- `a` — предыдущий блок,
- `d` — следующий,
- `c` — выход.

## Что получается на выходе

Словарь `dict_coords`:

```python
{
  1: [[1, (x1,y1), (x2,y2), "текст блока"], ...],
  2: [...],
  ...
}
```

Блоки на каждой странице отсортированы в порядке чтения. Это уже можно
использовать для:
- нарезки PDF на регионы,
- обучения/инференса layout-моделей,
- подачи в OCR или VLM,
- сравнения с разметкой других инструментов (например, MinerU).

## Что важно понимать про этот класс

1. **Он полностью опирается на `teiCoordinates` от GROBID.** Если GROBID не вернул
   координаты у `<p>` или `<s>`, блок просто теряется или обрабатывается через
   `extract_coords_v2`.
2. **Логика `smart_merge` — эвристика.** Она восстанавливает bounding box
   параграфа как многоугольник, а не как прямоугольник. Для однострочных блоков
   это неважно, для многострочных — уменьшает «пустые» области.
3. **Объединение вложенных и пересекающихся боксов — тоже эвристика.** IoU > 0 —
   довольно агрессивный порог: любые касающиеся боксы сливаются. Это может
   склеить соседние параграфы, если GROBID дал чуть перекрывающиеся координаты.
4. **Масштабирование зависит от DPI рендера.** Если поменять `convert_from_path`
   (например, добавить `dpi=...`), коэффициенты пересчитаются корректно только
   потому, что используется `resolution` из TEI.
5. **`remove_pdf_links` не вызывается** в `fit` — код удаления ссылок
   закомментирован. Это заготовка на случай, если аннотации PDF мешают рендеру
   или GROBID.
6. **`extract_header_info` хрупок к неполным данным.**
   `zip(forenames, surnames, emails, organisations)` обрежет список до
   минимальной длины — если у кого-то нет email, автор потеряется.

## Зачем это нужно

GROBID даёт **семантическую** разметку, но координаты в TEI — «сырые» и
неудобные: они в точках PDF, разбросаны по `<s>` внутри `<p>`, не отсортированы,
могут пересекаться. Этот класс превращает всё это в **чистое,
визуально-пространственное представление** — то, что обычно нужно для задач
верстки, сравнения с другими парсерами (MinerU, olmOCR, dots.ocr) или для
последующей обработки изображений.
